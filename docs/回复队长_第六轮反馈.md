先说结论：**你是对的，我上份报告那句"每次重新 exec、不污染 sys.path"不准确。**

实测（2026-10-22）：

```
>>> set(gateway_placeholders())          # 进程启动后第一次
{'请填写分析结果'}
>>> ai._PLACEHOLDERS = {'探针_缓存生效'}   # 手动篡改缓存
>>> set(gateway_placeholders())

```

进而做了一个更有说服力的实验——**在同一个 Python 进程里先建立缓存、再替换磁盘上的网关包**：

```
① 进程启动、换包前调用      -> ['请填写分析结果']
② 把磁盘上的包换成新版（示例值改成探针串）
③ 同一进程再调用            -> ['请填写分析结果']     ← 仍读不到新包
还原后 SHA256 与官方 SHA256SUMS 一致：True
```

**结论已经写进代码注释**（`src/backend/ai_interface.py` 的 `gateway_placeholders` docstring）：

- 结果只在**进程内首次调用**时算一次，之后由模块级 `_PLACEHOLDERS` 直接返回，**不会每次重读**；
- 加载过程中确实**临时**把包目录插入 `sys.path`，执行完 remove（调用返回时已不在里面，但过程中动过）；
- 由此产生一条硬性操作要求：**替换/升级 vendor 包之后必须重启后端**，热替换对这条路径无效。

### 2. 迁移脚本不认 --db，会静默写到正式库

写部署说明时实测场景 B，发现：

```
$ python migrate_review_history.py --db data/tmp_old.db
```

这些老脚本里的 `DB_PATH` 是 **import 时就固化的默认值**，命令行 `--db` 参数完全没被解析。
后果是最危险的一类 bug：**你以为在 A 库上做实验，实际在正式库上**，而且一句话都不提示。

✅ 已处理：

- `db.py` 新增 `apply_cli_db()`，统一从命令行认 `--db 路径` / `--db=路径`
- 六个脚本接上（`migrate_review_history` / `migrate_practice_tables` / `migrate_question_bank` /
  `migrate_question_type` / `migrate_subject_code` / `seed`）；
  `migrate_question_bank.py` 用的是 argparse，单独补了 `--db` 解析
- 修完重测，同一条命令现在打到的是 `data\tmp_old.db`，**不再碰正式库**
- `init_db.py` 原来还绕过了单一配置（自己 `sqlite3.connect` 直连默认库），一并改成走 `resolve_db_path()`
