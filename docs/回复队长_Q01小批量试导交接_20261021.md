## 二 字段确认：v2 结构与您的 19 列表头对齐

### 2.1 卷型与来源编号

| 您的要求 | 落实方式 |
|---|---|
| 数学一二三、英语一二另设卷型字段 | `paper_variant`：`MATH_1/MATH_2/MATH_3/ENGLISH_1/ENGLISH_2`。`subject_code` 仍只有五类，靠卷型区分不同卷，不会合并 |
| 每条题目有稳定的 `source_question_id` | 规则写死在迁移与导入两处：`{subject_code}｜{卷型}｜{场次或年份}｜{套数}｜{题号}`，例 `POSTGRAD_MATH｜MATH_2｜2022｜1｜17`、`CET4｜-｜2024-06｜1｜36`。它是 UNIQUE 主键，也是导入幂等的依据；同表另有 `UNIQUE(subject_code, source_file, question_no)` 作兜底 |
| 四六级区分年份、场次、套数 | `year` / `session`（如 `2024-06`）/ `paper_set` 三个字段分开存 |
| 题号保留原编号与子题信息 | `question_no` 是 TEXT，子题直接存（`36`、`36(1)`）；按选项二次切出的题存成 `25+1` 并置 `derived=1` 标记可靠性低 |

### 2.2 v2 字段（30 列）

**您给的 19 列全部采用且列名一致**（顺序即 CSV 模板顺序）：
`source_question_id, subject_code, paper_variant, year, session, paper_set, question_no,
question_type, knowledge_points_json, stem, options_json, answer, explanation, source_file,
source_pages_json, image_refs_json, audio_refs_json, material_id, status`

**我补了 11 列，都是溯源与审计用，请一并确认**：

| 字段 | 为什么必须留 |
|---|---|
| `section` | 大题名（`Part I` / `一、单项选择题`），没有它无法定位题在卷里的位置 |
| `analysis_file` | 解析 PDF 相对路径。样本 9 个解析 PDF 全是扫描件，答案只能人工补，必须记下该去看哪个文件 |
| `print_page` | 印刷页码。您要求与 PDF 页序分开，故另设字段（`source_pages_json` 只存 PDF 从 1 开始的页序） |
| `file_sha256` | 来源文件指纹，用于**文件级**去重 |
| `text_source` | `pdf_text / ocr / manual / empty / unknown`，一眼看出哪题是扫描件空壳 |
| `text_chars` | 提取字符数 |
| `derived` | 是否按选项二次切出，可靠性低，人工校对优先看这些 |
| `review_note` | 人工核对备注 |
| `created_at` / `updated_at` | 审计 |

v1 → v2 的字段映射（写死在 `migrate_question_bank_v2.py` 的 `CARRY` 常量里，两边不会各说一套）：
`question_text→stem`、`options→options_json`、`answer_text→answer`、`analysis→explanation`、
`no_in_paper→question_no`、`audio_file→audio_refs_json`（字符串转 JSON 数组）。

### 2.3 判分规则与空值语义（写死在 `question_bank_csv.py` 校验 + `api.py` 判分，改一处要改两处）

| 题型 | `answer` 存什么 | 判分规则 |
|---|---|---|
| `single_choice` | 单个字母 `A` | 去空格后精确比较，不分大小写 |
| `multi_choice` | 字母串 `ABD` | **字母集合相等、顺序无关**；校验时要求至少两个字母 |
| `true_false` | `A`/`B` 或 `T`/`F` | 同单选 |
| `blank / short_answer / translation / writing / compute` | **文字参考答案** | **不自动判分**，接口返回 `correct=null`、`needs_manual=true`，只把参考答案回给前端展示。主观题绝不做选择题式精确字符串比较 |

空值语义（明确写死，避免"空"和"没有"混为一谈）：
- `stem` 空串 = 该题确实没有书面题干（听力题题干在音频里、完形填空题干在文章里），**不是切分失败**；
- `answer` / `explanation` 为 NULL = 还没拿到答案（本批全部如此，因为解析 PDF 是扫描件），**不填占位符**；
- `options_json` 为 NULL = 无选项（主观题）；
- `audio_refs_json` 为 NULL = 该题不依赖音频；**注意与"该卷缺音频文件"是两件事**，分开登记。

### 2.4 共享材料

`material_id` 用于听力共用与阅读共享文章，取值如 `四级|2024-06|listening|四级_2024-06_第1套`。
共用听力（不带套号的 `四级_2024-06_听力.mp3`）会生成 `...|共用` 的 material_id，
让多套卷指向同一份材料，**不复制音频文件**。

## 三 运行保护（您第四节的六条，逐条落实）

1. **单一配置**：`db.py` 里只有 `resolve_db_path()` 一个函数决定库路径，优先级固定
   `--db` > 环境变量 `LEARNING_DB_PATH` > 默认正式库。**任何写库动作之前**调用
   `announce_db()` 打印：数据库来源、实际绝对路径、是否存在与大小。
2. **服务端数据库明确**：`api.py` 启动时打印同样三行，`/health` 增返回
   `database`（绝对路径）与 `database_source`。`tools/verify_v22_fixes.py` 现在开工前先
   拉 `/health` 并支持 `--expect-db`，服务端连的库与期望不一致**直接退出**，不再出现
   "以为在验测试库、实际打的是业务库"。
3. **迁移有备份、版本、重复执行检查**：`db_backup.py` 用 `sqlite3` 的 backup 接口
   （WAL 期间 `shutil.copy` 会拷坏），备份后做三层校验：integrity_check → 关键表 → 必要字段，
   外加与源库逐表比对行数。版本记在 `schema_migrations`，**重复执行直接跳过**；
   v1 表先改名 `question_bank_v1_archive`，搬完数据且行数核对一致才删。
4. **导入默认增量**：没有清空动作，不删用户错题。
5. **只检查不写入**：`--dry-run`（PDF 与 CSV 两条路都支持）。
6. **事务策略明示**：默认**整批提交**，任一步异常整批回滚并在报告写明；
   需要"错了只丢一条"时用 `--commit-each`。报告里 `txn` 字段会记录本次用的是哪种。

错误报告逐条带 **文件 / 题号（或 CSV 行号）/ 字段 / 原因**，`--report` 导出 JSON。
冲突**不覆盖**：库中 `status` 为 `pending_review` / `verified` 的题，导入只记
`question_bank_conflicts` 等人工裁决，原内容一个字不动。

三种去重分工明确、不互相替代：`file_sha256` 查重文件、`source_question_id` 查重来源编号、
`stem` 参与的内容查重（批次内编号重复也进冲突清单）。
