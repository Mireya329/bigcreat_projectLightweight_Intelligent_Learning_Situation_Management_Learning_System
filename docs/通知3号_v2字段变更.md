# 通知 3 号：v2 协议字段变更（覆盖上一版通知，以此版为准）

> 3 号，队长 10-09 下发了 v2 协议，字段名大改。**我上一版通知里有一条规则是错的**，
> 会导致你的统计算错，麻烦按这版改。改动集中在三处，其余不变。

---

## 一、【必须改】待复核的判定规则变了

上一版我写的是：

> ❌ 旧说法：`review_flag = 'pending_review'` 时，`error_type` **一定是** `null`

**这条是错的。** v2 口径是：**只看 `review_flag`，不看 `error_type` 是否为空。**

库里就有实例——`id=13`：

```json
{ "id": 13, "error_type": "calculation_error", "review_flag": "pending_review" }
```

分类非空，但它**仍是未确认**的。原因是这道题没有学生作答，AI 的判断是凭空的，
所以保留了原分类值当审计痕迹，同时打上待复核标记。

**你的代码要这么写：**

| 场景 | 判断依据 |
|---|---|
| 饼图 / 分类统计 | `review_flag IS NULL` **且** `error_type IS NOT NULL` 才计入具体类别 |
| 待复核计数 | 只数 `review_flag = 'pending_review'` |
| 列表标签 | 看 `review_flag`，不看 `error_type` 有没有值 |

如果你按旧规则写（`error_type` 非空就算已确认），id=13 这类题会被算进"计算失误"，
**饼图百分比直接错**。

我侧统计接口已经改好并验证过：11 行数据里 7 行待复核全部排除，四类分布一个都没进。

## 二、【不要用】`error_type_conf` 这一列别碰

`/errors` 返回里有个 `error_type_conf`，**这一列语义是乱的，请不要使用**：

- 待复核时它存的是 `"pending_review"`（这是状态）
- 不待复核时它存的是 `"high"` / `"low"`（这是置信度等级）

两种语义混在一列里，是我早期留下的历史列，现在只是保留不删。

**要什么用什么：**

| 你要的东西 | 用这个字段 |
|---|---|
| 置信度（数值） | `error_confidence`（0~1 的小数，如 `0.6`） |
| 是否待复核 | `review_flag`（`'pending_review'` 或 `null`） |
| 判定依据（可展示给用户） | `error_reason` |

| code | 中文 |
|---|---|
| `concept_misunderstanding` | 概念不清 |
| `calculation_error` | 计算失误 |
| `misread_question` | 审题偏差 |
| `method_gap` | 方法缺失 |

## 六、`judge_fragment` 的实测结论（已跑完，供你判断要不要接）

这个场景是 OCR 切分漏题时的兜底判断：一段残片到底是不是被漏掉的题。
**它跟前面那些不一样，判错会往库里补一道不存在的题**，所以单独说。

同一批 5 个样本 × 3 次，两个模型对照：

| 模型 | 三次判定完全一致 | 表现 |
|---|---|---|
| 0.5b（旧） | **0 / 5** | 完全随机，同一段文本能跑出 A/B/C 三种 |
| 7b（现在） | **4 / 5** | 明显稳定，仍有 1 例摇摆 |

结论：**7b 有质的改善，但没到能放心自动补题的程度**。所以强制兜底保留——
多轮判定不一致时一律按"无法判断"处理，不写库。

另外加了一条硬约束：**判定为"这是一道独立题"时，模型必须同时给出题干**，
给不出就按不合法处理。因为只有这个结论会往库里插新题，
不能靠模型自觉。（实测 7b 会给，但那是模型表现，不是契约保证。）

**对你的影响**：如果前端要展示"AI 补录的题目"，这些题的来源要标清楚，
不能跟用户自己录入的题混在一起展示。

## 七、没变的部分

- `error_type` 四个 code 不变（`concept_misunderstanding` / `calculation_error` /
  `misread_question` / `method_gap`）
- `/errors`、`/errors/{id}` 的接口路径和参数不变
- 展示建议不变：待复核的题不要当成确定结论，措辞用"AI 初步判断"
