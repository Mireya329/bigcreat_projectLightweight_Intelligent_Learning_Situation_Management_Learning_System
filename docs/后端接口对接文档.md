## 三、接口清单一览

| 方法 | 路径 | 用途 | 前端谁会用 |
|---|---|---|---|
| GET | `/health` | 服务/数据库/Ollama 状态 | 健康检查 |
| GET | `/stats` | 跨线学情统计 | 学情看板 |
| GET | `/errors` | 错题列表（可筛选） | 错题列表页 |
| GET | `/errors/{id}` | 单题详情（含标签） | 错题详情页 |

| POST | `/words/practice` | 上报单词练习记录 | Qwerty Learner 打完一个词 |
| POST | `/practice/quiz` | 上报刷题记录（趋势图/正确率数据源） | 做题页，一次练习结束汇总上报一次 |

## 四、接口详解（含可直接用的 fetch 代码）

### 1. 健康检查 `GET /health`

```js
const r = await fetch('http://127.0.0.1:8000/health').then(r => r.json())
// { status:"ok", database:"...\\learning.db", ollama_online:true, model:"qwen2.5:0.5b" }
```

### 2. 学情统计 `GET /stats?username=test`

返回结构（单词线和错题线一起，**这就是统一数据库的产物**）：

```json
{
  "word": {
    "practice_count": 200,
    "distinct_words": 200,
    "perfect_rate": 50.0,
    "total_wrong": 200,
    "avg_sec_per_word": 1.69,
    "top_wrong_words": [{"word":"carrier","wrong":3,"count":1}]
  },
  "error": {
    "by_subject": {"数学": 11},
    "by_mastery": {"未掌握": 11},
    "due_review": 0,
    "ai_parsed": 7,
    "gated": 2,
    "manual": 2
  }
}
```

### 3. 错题列表 `GET /errors`

可选参数：`username`、`subject`（如"数学"）、`mastery`（0/1/2）、`limit`（默认 50）

```json
{
  "count": 3,
  "items": [
    {"id":12,"question_text":"Ox100001\nf(x0+∆x,y0+∆y)−...",
     "source":"习题二...｜一、选择题 第0题（行8-29）",
     "mastery_level":0,"ocr_quality":45,"ai_model":"quality_gate","subject":"数学"}
  ]
}
```

### 4. 错题详情 `GET /errors/{id}`

在列表基础上多返回完整字段（含 `analysis` AI 解析正文）和 `tags` 数组。

### 5. 新增错题 `POST /errors`

```js
await fetch('http://127.0.0.1:8000/errors', {
  method:'POST',
  headers:{'Content-Type':'application/json'},
  body: JSON.stringify({
    username:'test',
    question:'设 z = x^2 y + sin(xy)，求 ∂z/∂x 与 ∂z/∂y。',
    subject:'数学',
    source:'手动录入',
    tag:'偏导数与高阶偏导数'
  })
})
// 返回 {"id":24,"ocr_quality":85}
```

后端会自动做三件事：**质量打分 → 打知识点标签 → 排 3 天后的复习计划**。

### 6. 更新掌握度 `PATCH /errors/{id}/mastery?level=1`

`level`：`0` 未掌握 / `1` 复习中 / `2` 已掌握。传别的值返回 400。

### 7. 待复习 `GET /review/due`

返回到期待复习的错题（`scheduled_for` 已到、且未完成）。

### 8. 易错词排行 `GET /words/wrong-top?limit=10`

```json
{"count":3,"items":[
  {"word":"carrier","trans":"[\"运输工具， 运载工具； 带菌者\"]","wrong":3,"times":1}
]}
```

⚠️ **`trans` 是 JSON 字符串，不是数组**，前端要 `JSON.parse(trans)` 再用。

### 9. 上报练习记录 `POST /words/practice`

```js
await fetch('http://127.0.0.1:8000/words/practice', {
  method:'POST', headers:{'Content-Type':'application/json'},
  body: JSON.stringify({
    username:'test', word:'carrier', dict_key:'CET4_T',
    wrong_count:2, total_time_ms:1800, chapter:0
  })
})
// {"word":"carrier","linked":true}   linked=false 表示这个词不在词库里
```

## 五、字段约定（前后端必须对齐，不然会出隐性 bug）

### `mastery_level`（掌握度）

| 值 | 含义 | 前端显示建议 |
|---|---|---|
| 0 | 未掌握 | 红色"待攻克" |
| 1 | 复习中 | 黄色"复习中" |
| 2 | 已掌握 | 绿色"已掌握" |

### `ocr_quality`（OCR 可信分，0-100）

- **< 70 的题已被质量门禁拦下，不会送 AI**
- 前端遇到低分题，应显示"**题目识别质量低，请人工确认**"提示，而不是直接展示 AI 解析（因为可能没有解析）
- **100 分 = 人工录入**（人工确认过，质量最高）

### `ai_model`（这条解析是谁产出的）

| 取值 | 含义 | 前端处理 |
|---|---|---|
| `qwen2.5:0.5b` 等模型名 | AI 已解析 | 正常展示 |
| `quality_gate` | 被质量门禁拦下，未送 AI | 显示"需人工确认"，**不要展示解析** |
| `manual` | 人工补录 | 正常展示 |
| `NULL` | 还没解析 | 显示"解析中/待解析" |

### `trans`（单词释义）

存的是 **JSON 字符串**，前端必须 `JSON.parse()`。

## 六、两个前端项目怎么接（建议，待组长拍板）

### wrong-notebook（Next.js 错题本）

它现在用的是自己的 Gemini/OpenAI 接口。改造思路：

1. **保留它的 UI**，把它的 `/api/analyze`（AI 解析）改成转发到我们的后端
2. **OCR 换成我们的 PaddleOCR**：调用 `src/backend/ocr_fast_run.py`（整卷 ~73 秒，比它原来的方案快很多）
3. **数据落到我们的 `error_items`**：用本文档的 `POST /errors`

> 它自带 Prisma + SQLite，我们也是 SQLite，但**表结构不同**。二选一：①让它读写我们的库 ②做个同步脚本。我建议 ①，避免两份数据不一致。

### Qwerty Learner（React 单词）

1. 它本身是纯前端（IndexedDB），练习数据不出浏览器
2. 改造点：**每打完一个词，POST 一条到 `/words/practice`**
3. 词库我们已经导入了 2607 个 CET4 词（`dicts` + `words` 表），前端可以直接从 `/words/wrong-top` 拿弱项词复习

## 八、已知限制（提前说明，免得队友踩坑）

1. **AI 质量不可用于演示**：0.5b 输出不稳定，同一输入可能给出不同结论，还会编造
2. **切分召回率 75%**：12 道题的卷子能自动切出 9 道，漏的 3 道已生成 `pending_manual.json` 待人工补录
3. **质量门禁会拦题**：这是**故意的**——宁可拦下让人确认，也不让 AI 对着垃圾编解析
4. **单词练习数据是演示数据**：200 条是脚本生成的，真实数据要从 Qwerty Learner 导出后导入
5. **没有鉴权、没有并发保护**：本地单用户开发阶段够用，上生产前必须补
