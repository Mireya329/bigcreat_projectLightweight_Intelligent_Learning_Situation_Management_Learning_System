# 通知 3 号：错题分类字段变更（可直接复制发送）

> 3 号，队长那边下发了 AI 对接协议，我这边今天按协议改了后端，
> **有两个字段的取值变了，会影响你的图表和筛选**，麻烦同步改一下。

---

## 一、`error_type` 取值全换了（重点）

| 旧值 | 新值 | 中文 |
|---|---|---|
| `concept` | `concept_misunderstanding` | 概念理解错误 |
| `calculation` | `calculation_error` | 计算失误 |
| `misread` | `misread_question` | 审题偏差 |
| `method` | `method_gap` | 方法缺失 |

这四个 code 是队长协议里冻结的，不能改。**如果你已经按旧值写了饼图或筛选条件，要全部换成新值**，不然匹配不上（会全部落到"未分类"）。

## 二、新增三个字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `error_confidence` | 数字 0~1 | AI 对这个分类的把握程度 |
| `error_reason` | 文本 | 一句话判定依据，**可以直接展示给用户看** |
| `review_flag` | 文本 | `pending_review` = 待人工复核；`null` = 已自动入库 |

## 三、展示规则（这条别弄错）

**`review_flag = 'pending_review'` 的时候，`error_type` 一定是 `null`。**

原因：置信度 < 0.5 的分类我们不信任，不自动入库，只打标记等人确认。所以：

- ✅ 饼图/统计里这些题归到**「未分类」**，不要混进具体类别
- ✅ 列表里可以显示「待人工复核」标签，`error_reason` 可以展示（那是 AI 的判断依据，但明确告诉用户这是未确认的）
- ❌ 不要因为 `error_type` 是 null 就报错或当成异常，这是正常状态

## 四、接口变化

**`GET /errors`** 列表每项新增三个字段：
```json
{
  "id": 13,
  "error_type": "calculation_error",
  "error_confidence": 0.6,
  "error_reason": "精确命中类别词「计算失误」",
  "review_flag": null
}
```

**`GET /stats`** 的 `error` 段新增一个计数：
```json
"error": {
  "by_error_type": {"计算失误": 1, "未分类": 10},
  "pending_review": 6,
  ...
}
```
（以上是 2026-09-21 库里的真实值，只供你看结构，数字会随解析进度变）
`by_error_type` 的 key 已经是中文，你直接拿来画饼图就行，不用再做一次映射。

## 五、一个补充：分类不稳定，别把 AI 分类当事实展示

真机联调（2026-09-21，0.5b）测出来一件事，跟你的 UI 有关：

**同一道题跑三次，分类结果会变。** 5 题 × 3 次里只有 1 题三次一致。
连一道手写的干净题都跑出了三种分类。所以：

- 不要把 `error_type` 当成确定的事实去展示，比如"你的主要问题是计算失误"这种断言
- 建议措辞改成"AI 初步判断"，或者干脆在待复核状态下不展示分类
- 等 7b 到位重跑后我再跟你说能不能放开

另外 `error_type_label` 我侧已经修成**保证与 code 对应**了
（之前模型会把 `method_gap` 的标签写成"计算失误"）。
你要显示中文标签，直接用 `error_type_label`，四个值之一：
概念理解错误 / 计算失误 / 审题偏差 / 方法缺失。
