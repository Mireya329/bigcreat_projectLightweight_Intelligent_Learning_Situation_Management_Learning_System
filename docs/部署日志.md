### 步骤 13：zip 校验发现 2 个损坏块 —— 局部重下修复

症状：`zipfile.ZipFile` 打开正常，但逐个读条目时 2 个文件 CRC 校验失败，**都是 CUDA 库**：
- `lib/ollama/cuda_v12/cublas64_12.dll`（86MB）
- `lib/ollama/cuda_v12/cublasLt64_12.dll`（485MB）

解决：解析 local header 拿到这两个条目的精确字节区间 → 只重下损坏区间 → 覆盖写入 zip（fix_ollama_zip.py）。

结果：cublas64_12.dll ✅ 修复；cublasLt64_12.dll 第二次下载仍差 27MB（代理不稳定）。

### 步骤 16.1：发现 PaddlePaddle 3.3.1 + oneDNN 大图崩溃

**症状**：图片宽 ≥ 1280 像素时，`ocr.predict()` 静默崩溃（exit code 1，无 traceback，stderr 只有 Windows 系统消息 "信息: 用提供的模式无法找到文件。"）

**根因**：PaddlePaddle oneDNN 在某些图片尺寸下调用 `ConvertPirAttribute2RuntimeAttribute` 时不支持 `pir::ArrayAttribute<pir::DoubleAttribute>`（文件 `paddle\fluid\framework\new_executor\instruction\onednn\onednn_instruction.cc:118`）

**验证**：
- 小图（800×300）✅ 正常
- 中图（1280×480）✅ 正常
- 大图（1280×3893）✗ 崩溃
- 小图但缩放（1280×950）✅ 正常
- 小图但缩放（1280×1200）✗ 崩溃

### 步骤 16.2：尝试解决（多次失败）

| 尝试 | 结果 |
|------|------|
| `enable_mkldnn=False` 参数 | ❌ 无效（C++ 运行时仍加载 oneDNN） |
| `os.environ['FLAGS_use_mkldnn']='0'` | ❌ 无效 |
| `paddle.set_flags({'FLAGS_use_mkldnn': False})` | ❌ 无效 |
| 降级 paddlepaddle 3.0.0 + paddleocr 3.7.0 | ❌ "Type of attribute: strides is not right" |
| 降级 paddlepaddle 3.2.0 | ❌ oneDNN 崩溃仍在 |
| 降级 paddleocr 3.1.0 + paddlex 3.1.0 | ❌ API 兼容问题（"PaddlePredictorOption.__init__() takes 1 positional argument but 2 were given"） |
| 降级 paddleocr 2.7.3 | ❌ 缺依赖 `skimage` |

**最终方案**：切片 + 子进程隔离（见 16.3）

### 步骤 16.5：关键发现（给第 2 阶段）

1. **耗时严重不达预期**：实测 10 分钟/片，文档预估 1-3 秒/片。**第 2 阶段必须做性能调优**：
   - 单进程 OCR 实例（避免重复加载 5 个模型共 177MB）
   - 减小 `max_side_len`（如 960）
   - 改用 PP-OCRv5_server 模型（精度更高但更慢，需权衡）

2. **真实场景识别率偏低**：手写体（红蓝笔批注）几乎全部失败，这是项目必须解决的核心问题
