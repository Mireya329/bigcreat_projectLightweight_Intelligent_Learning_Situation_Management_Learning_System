## 3. judge_fragment 请求与响应样例

### 3.1 请求

```json
{
  "scene": "judge_fragment",
  "subject": "math",
  "input": {

    "next": "2. 设 z = arctan(y/x)，求 dz"

  "user_context": {}
}
```

### 3.2 成功响应（两轮判定一致）

```json
{
  "code": 0,
  "scene": "judge_fragment",
  "data": {
    "choice": "B",
    "guessed_no": "1",
    "stem": "已知 z=x^4+y^4-4x^2y^2，求 zx(1,2)",
    "qtype": "计算题",
    "reason": "以题号开头且是完整提问，属被漏切的独立题",
    "stable": true
  },
  "raw": { "rounds": [ ... ], "stability_note": "2 轮判定一致（B）" },
  "model": "qwen2.5:0.5b",
  "elapsed_ms": 0,
  "protocol": { "version": "2026-09-21-captain-v1",
                "code2": "模型输出格式不合法（后端重试 1 次）",
                "retry_owner": "backend" }
}
```

A=上一题延续、B=被漏掉的独立题、C=无法判断。

### 3.3 失败响应一：两轮不一致 → 强制判 C，**不入库**

```json
{
  "code": 0,
  "scene": "judge_fragment",
  "data": {
    "choice": "C",
    "reason": "[判定未通过稳定性校验] ['A', 'B']，按无法判断处理",
    "stable": false
  },
  "raw": { "rounds": [{"code":0,"data":{"choice":"B",...}},
                      {"code":0,"data":{"choice":"A",...}}],
           "stability_note": "2 轮判定不一致（['A', 'B']），强制判 C" },
  "model": "qwen2.5:0.5b", "elapsed_ms": 0
}
```

注意 code 仍是 0——两次调用本身都成功了，只是结论互相打架。
判 C 意味着"无法判断"，下游视为 unknown，**不会往 error_items 插记录**。
这是我侧主动加的防护：这个场景判错会往库里补一道不存在的题，比不补更糟。

### 3.4 失败响应二：输出不合法 → 降级

```json
{
  "code": 1, "scene": "judge_fragment", "data": null,
  "raw": { "text": "也不是", "reason": "返回不是合法 JSON 对象", "retried": 1 },
  "model": "qwen2.5:0.5b", "elapsed_ms": 0
}
```

3 个用例 × 3 次：**3/3 结果不一致**。所以上面 3.3 的强制判 C 在 0.5b 上
