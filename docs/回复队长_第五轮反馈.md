## 二 四项待修点：改法与验证证据

验证脚本 `tools/verify_v22_fixes.py`，**23 项全部通过**，跑在测试库副本上。

### 1. 占位符动态加载路径（你说的完全正确）

原实现 `Path(__file__).resolve().parents[1]` 从 `src/backend/ai_interface.py`
算出来是 `src/`，拼成 `src/vendor/captain_ai_v2` —— **该目录不存在**，一直走兜底。
我实测确认过：`(路径).is_dir()` 返回 False。

改法：改用已有的 `CAPTAIN_PKG_DIR`（项目根 `vendor` 下），并且用
`importlib.util.spec_from_file_location` 以私有模块名 `_captain_shape_probe`
每次重新 exec，既不污染 `sys.path`，也避开 `sys.modules` 缓存住旧包。
兜底常量保留（网关可能仍是旧版本），但**不再允许它掩盖路径错误**。

你说"当前测试只检查读到旧文案，即使走兜底也通过"——这正是问题所在，
所以我加了 v2-9 组隔离测试：**复制一份包、把示例值替换成探针字符串**，
再断言探针值出现在结果里。只有真的动态加载成功才会通过。
附带断言：兜底值仍在（兼容旧网关）、`CAPTAIN_PKG_DIR` 指向真实存在的包。

### 2. 作答变更后旧确认状态未失效

改法（`api.py` 的 `set_answer`）：

- 修改前后做 strip 后比较，**仅在内容实际改变时**才动状态；
- 改变且该条原本是 confirmed 或有分类 → 归档旧结论到 `error_review_history`，
  再把 `review_flag` 置为 `pending_review`；
- 内容没变的重复提交 → 不动（前端手抖点两次不该刷掉确认）。
- 返回体新增 `changed` / `previous_conclusion_invalidated` / `review_flag` 三个字段。

验证证据：

| 用例 | 结果 |
|---|---|
| 提交与原文相同的作答 | `changed=false`，`review_flag` 仍是 confirmed ✅ |
| 改动作答 | `review_flag` → pending_review，`previous_conclusion_invalidated=true` ✅ |
| 统计口径 | `/stats` 的 `error.confirmed` **1 → 0**（不再计入已确认） ✅ |
| 归档 | 归档表有 `answer_changed` 记录，保留了旧 error_type 和旧作答 ✅ |

### 3. 强制分析后状态不一致

原写法 `review_flag=COALESCE(review_flag,'pending_review')` 保留 confirmed，
返回体却固定写 `pending_review`——两边打架，你点得对。

我明确的转换规则：**重分析成功 = 产生了新的候选结论，旧的已确认分类对新结论不再适用**
→ 库里一律写成 `pending_review`，返回体**回读数据库**后再返回（结构上杜绝不一致），
同时把旧人工结论归档。重分析失败（code≠0）**不碰任何状态**。

验证证据：

| 用例 | 结果 |
|---|---|
| 返回体 vs 库 | 两边都是 `pending_review`，同一查询取值一致 ✅ |
| force 前状态回传 | 新增 `previous_review_flag=confirmed`，如实告知被推翻的是什么 ✅ |
| 统计 | force 后 `error.confirmed` 1 → 0 ✅ |
| 归档 | `reanalyzed` 记录里保留了旧 `error_type=calculation_error` ✅ |

### 4. 确认时可能没有有效分类

改法：`decision=confirmed` 时，先算"本次提交的 error_type"或"库里已有的 error_type"
是不是四个合法 code 之一；不是就返回 **400 + 可理解的中文说明**，**不修改任何状态**。
`rejected` 不要求分类（退回待复核本来就不给结论）。

验证证据：

| 用例 | 结果 |
|---|---|
| 新题 confirmed 且无历史分类 | 400，且复查该行 `review_flag` 仍为 NULL（没被改） ✅ |
| 带合法 error_type 确认 | 200，confirmed ✅ |
| 已有合法分类、本次不带 error_type | 200，沿用它确认 ✅ |
| rejected 不带分类 | 200，pending_review ✅ |

算出了数值但**没有"最终答案："这类结论标记**，所以按规则不补全、判失败。

**如实声明三点**：

1. 库里 id15 的题干仍是 OCR 残片（75 字，含 `-2x / 2y / x+y / (x-y/^2+(x+y)2}` 等碎片），

3. 修正题干需要原图或人工转写，按你第六节的分工，我等四号给完整题干后再做解题质量验收，
   脚本已经备好（换 `--id` 即可）。

顺带一个观察（不改你的包，只提给你判断）：模型在重试时其实把答案算到了 `= 1`，

要不要放宽（例如末步出现 `= 数值` 且形如最终式也算结论），由你定，我跟着改。
