## 条目 3：交互环境粘贴多行代码报错（2026-09-13 16:42）

**操作**：在 Python 交互环境里粘贴多行 for 循环做质量检查。

**报错**（3 个，全部是语法/缩进类）：
```
SyntaxError: invalid syntax            ← 粘贴进了未结束的 ... 续行块
IndentationError: unexpected indent    ← 带缩进的行单独粘贴
IndentationError: unexpected indent
IndentationError: unexpected indent
```

**原因**：
1. 第一次粘贴时上一条 for 语句还在等待缩进块（提示符是 `...` 而不是 `>>>`），新代码粘进去把块结构弄乱 → SyntaxError
2. 之后带前导空格的行（如 `    print(...)`）被逐行单独执行，交互模式不允许"裸"缩进 → IndentationError

**教训（交互模式粘贴铁律）**：
- 看提示符：`>>>` 才是干净状态，`...` 说明上一条还没结束（先按回车/退格清掉）
- 多行带缩进的块在交互模式极易粘贴出错 → 要么写成单行（`for t in x[:5]: print(t)`），要么存成 `.py` 文件跑
- 数据分析这类多行代码建议直接写脚本文件，别在交互环境拼

**解决**：改用无缩进的单行写法重跑质量检查（见条目 4）。

## 条目 16：任务 C · STEP 8 错题切分实验——7/10 题（2026-09-15 18:10~18:26）

**操作**：新建 `src\backend\ocr_split.py`，用两条正则对 `all_text.txt`（116 行）切题：
- 章节：`^([一二三四五六七八九十]+)、(.+)$`
- 题号：`^(\d+)\s*[.．、](.+)$`（兼容 `1.`、`4.设`、`3、` 三种写法）

**结果**：
```
共切出 7 道题（选择题 1 / 填空题 2 / 计算题 4）
第1题 选项数 7 个，其余 0 个（符合预期：只有选择题有选项）
```

**分析（本次核心发现：OCR 的题号识别不可靠）**：

| 应切 | 实切 | 丢失原因 |
|---|---|---|
| 选择题 3 题 | 1 题 | 第 1 题题号被 OCR 认成 `Ox100001`（"1." 识别失败）；第 3 题题号行整行丢失，仅残留孤立选项组 |
| 填空题 2 题 | 2 题 | ✅ 完整 |
| 计算题 5 题 | 4 题 | 第 2 题题号行丢失，内容混在手写笔记区（行 68~84） |

**召回率 7/10 = 70%**。结论：**纯正则只能做粗切**，题号丢失是 OCR 的固有缺陷，不是代码 bug。

**下一步补救方案（按成本递增）**：
1. 人工标注 `golden_splits.json` 作为切分验收基准（没有标准答案的优化都是盲调）
